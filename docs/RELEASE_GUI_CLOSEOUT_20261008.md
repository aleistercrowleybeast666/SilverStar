## FLP 根因和修改

9% 对应全数据集缓存的数组序列化入口：全局范围 `0.08..0.40` 的局部
`0.05` 为 `0.096`。46% 对应全 run 结果缓存序列化入口：`0.45..0.78`
的局部 `0.05` 为 `0.4665`。此前进入 `np.save(gzip)` 后没有内部工作量回调，
哈希循环同样没有逐块报告，阶段结束前百分比看起来停住。

- `core/artifacts.py` 将数组压缩/读取限制为每块最多 1 MiB；哈希、对象遍历、
  JSON、记录块、时间戳验证报告实际字节或对象量，并检查取消。
- 整个序列化阶段的总工作量无法可靠提前确定，因为记录块会生成数组；界面
  显示“处理中”、明确阶段及实际累计处理量。已知数组读取和哈希范围按真实
  字节推进。计时仅用于约 10 Hz 的 GUI 更新节流，不用于百分比估算。
- 保存与打开的哈希回调放入各自单调阶段范围；打开缓存也有细粒度报告。
- 耗时工作沿用后台 worker；100% 仍须原子提交及 GUI 成功发布。
  未删减诊断、身份/哈希/结构校验、取消、全 run、主副源恢复、删除 run、
  配置-only 不自动重算等行为；未改历史 worker 生命周期逻辑。

主要文件：`apps/FLP/src/silverstar_flp/core/{artifacts,project}.py`、
`log_open.py`、`ui/{main_window,workers}.py`、双语资源，以及新增字节进度测试
和扩展受控慢写入测试。

## SCG 根因和修改

此前 UI 沿用插件声明的普通实例上限；档位切换还会静默筛掉超限/GNSS 设备，
历史档位快照恢复也可能替换当前设备。限制没有完整覆盖所有传感器类别和入口。

- 内部 `full/standard/compact/minimal` 和 schema 保持兼容；中文固定为
  完整、标准、轻量、最简。
- 轻量/最简对每种传感器类型独立限制一个实例，同时最多一个遥测实例；
  轻量允许单 GNSS。最简禁止启用、选择和添加 GNSS。
- 新增与选择入口、配置服务、工程载入提示及源图/生成校验使用同一约束。
  导入或切档后的冲突设备保留，显示提示并阻止生成，用户可删除或切回普通档。
- 删除后允许补一个；完整/标准恢复普通声明上限。回到已保存档位时设备、
  绑定和源覆盖保留当前编辑，避免旧快照静默隐藏新增设备。
- 最简关闭维护协议仍沿用既有自动管理维护传输的规则，未将维护虚拟实例
  算作用户传感器。

主要文件：`apps/SCG/src/silverstar_fccg/project/{feature_tiers,compact,configuration}.py`、
`app/service.py`、`ui/main_window.py`、`ui/pages/components.py`、双语资源及档位测试。
