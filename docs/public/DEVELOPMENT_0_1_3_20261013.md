这是本地开发成果，不是新发布包或硬件验收结论。唯一开发分支为
`feature/usb-transport-0.1.3-20261013`。冻结的 `v0.1.2` tag 对象仍为
`942f20ef64df3cb1aa65be7349361c409418aa0f`，指向原始发布提交 `c31c13c`。

## 架构与交付

| 层次 | 本轮实现 | 边界 |
| --- | --- | --- |
| CubeMX 芯片工程 | 只读检查完整 `.ioc`、CDC、启动、中断、栈和构建文件 | 原工程继续拥有时钟、引脚、PCD、IRQ、初始化及原生 USB 栈；导出器不覆盖它 |
| SCG USB kit | 独立导出、通用静态收发缓冲、会话代号、BUSY、背压、断开和取消确认接口；classic legacy/indexed 两种 ABI 适配 | 实验性 FS 单 CDC；USBX、HS、DMA/cache、复合设备及额外并发模型需要独立适配，不能按系列名承诺支持 |
| 固件文件服务 | Console `LOGFILE v1` 的 CAPS/LIST/META/READ/POLL/CANCEL，LoggerTask 独占 FatFs | 只读历史任务；当前任务始终排除；无 AIR/GSP 无线批量下载绑定 |
| Windows GSHC | 保留原三页，增加“调试与维护”；顶部 Ground 与独立 FC 调试口；文件传输、进度、校验和只读诊断 | 两路可能连接不同飞控，设备身份未绑定；任务命令仍走 Ground，文件服务只走调试口 |
| 文件格式 | `session-export v1` 清单、SHA-256，新 JSONL SESSION_START 格式声明 | SSLOG 容器 0.0、原始日志字节、Descriptor、`.ssdecoder` 1.2 保持原有语义；FLP 仍需精确匹配的 decoder |

USB 的[小型架构和兼容矩阵](../../apps/SCG/docs/USB_CDC_TRANSPORT_20261013.md)
列出明确的实验支持和拒绝理由。新适配器只在 Host 执行，并与真实 F103C8T6、F407VET6
工程完成 ABI 编译链接；**尚未接入这些工程的实际原生 USB 回调**。USB kit 不会自动接上
Console 文件服务；目前文件服务沿用已有维护 UART。可选 DAPLink VCP 可作为 UART 桥，
其支持取决于实际探针固件，MSC 拖放盘不是飞控 TF 卡。

未知 device/boot 身份下，每次下载都从零开始。CRC/长度 token 只用于变化检测，不是稳定身份。
DELETE 始终返回 UNSUPPORTED，CAPS 的 `delete_supported=0`；没有固件 unlink 后端。
今后远程删除和续传需要新的身份契约及单独的确认流程。

Windows 的[操作、线程和完整性说明](../../apps/GSHC/docs/LOG_TRANSFER_20261013.md)
区分 TF 文件下载与本地会话导出。复制保留源；剪切仅限单个已关闭的受管 JSONL，目标关闭、
SHA-256 回读和清单校验通过后，另行确认并重新校验才删除本地源。
TF 下载前单独选择目标目录；写入探测成功后显示并记住该目录。文件位于其新的
`SilverStar_download_*` 子目录，重名不覆盖。空间预检之后仍检查实际写入和 fsync 结果。
未完成文件使用 `.partial` 与诊断 JSON；元数据明确 `resume_allowed=false`，不能用于 v1 续传。
只有完整校验通过才原子发布最终日志。取消选目录不会启动传输，写入故障保留设备源文件。
普通文件系统/已挂载目录可作为目标，MTP 手机不是本轮文件系统适配器。
服务层保留未来本机 AI 调用入口，但没有新增 HTTP/MCP 服务、监听端口或凭据。

## 尚未满足的验收条件

1. 严格栈检查失败。需要审计 Console/SerialTask 和 LoggerTask/FatFs/diskio/HAL 的完整调用路径、
   实际绑定、动态/间接帧、第三方函数、MSP 与中断嵌套，建立证据后重新运行检查。
2. 最终 F407 主 SRAM 为 102388/131072，距离现有 102400 字节项目门限仅 12 字节；
   CCM 为 59400/65536。通过内存门限不证明栈余量。
3. 64 字节 READ 每次执行 open/seek/read/close；FatFs seek 可能遍历簇链。
   分块大小不证明 LoggerTask 截止时间、看门狗预算、碎片文件延迟、吞吐或 MCU WCET。
4. 取消竞争及 close 故障已有修复后回归，但未保留对应修复前源码/失败可执行结果；
   不能声称该 safety batch 的前后证据完整。不得逆向删除保护制造“旧版失败”。
5. USB 端点真实取消、LL 错误传播、实际回调接入、USB 时钟/IRQ、枚举、断线重连、
   多 USB/Hub、TF 卡及各型号上板验证尚未完成。
