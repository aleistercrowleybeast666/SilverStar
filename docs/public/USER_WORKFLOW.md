# 三工具共用操作路线（0.1.2）

从[根README](../../README.md)安装共享Python环境，再阅读[身份与证据边界](shared/VERSIONS_AND_EVIDENCE.md)。三应用共享项目/协议身份，各自承担不同职责。

1. 在[SCG](SCG/APP_README.md)选择外部工程目录、设备、档位、导航与协议，绑定真实硬件资源。四档不与MCU永久绑定；未知配置拒绝，导入/重开后的冲突需要用户明确修正。
2. 分别生成Flight/Ground到项目目标目录，使用[构建说明](SCG/BUILD.md)检查实际工具/SourceGraph/CPU/linker。正常再生成保护用户拥有的payload；若需模板修复，使用新隔离工程或明确迁移并重建。
3. 记录工程配置、实际固件与根exact `.ssdecoder`的对应关系，保留原产物和输入。只有经过明确硬件授权及相应板级核对的流程才能连接/烧录；本次文档和打包没有执行硬件操作。
4. [GSHC](GSHC/APP_README.md)依据AIR M0采集和显示地面状态。ACK不是READY；命令前提以权威状态为准。有界队列和诊断保持显式，不把显示窗口裁剪等同持久日志裁剪。
5. [FLP](FLP/APP_README.md)打开日志/精确decoder或SilverStar项目根；检查Descriptor、身份、完整性，再选择Recorded/重算主源及可选副源。原始输入不可改写，缺实际配置不能用默认值补成Recorded。
6. 按实际数据源、范围和选项保存/导出。阶段百分比不是持久提交；取消/失败保持旧项目与输入，重开校验工件，不自动数值重算。Windows路径过长时选择短目录/工程名，不能篡改源身份绕过检查。

理解惯导、SF6、KF6、ESKF15从[实现说明](algorithms/NAVIGATION_IMPLEMENTATION.md)进入，公式文档注明坐标/符号/假设/源码身份。日志或接收数据推导的轨迹不是位置真值；阶梯、空白和故障诊断不能为了展示插值/抹平。

源码推荐组合见[支持矩阵](SUPPORT_MATRIX.md)，它区分配置起点、历史证据和未验证项。公共文档不附实测用户数据、串口连接脚本或内部审查结果；具体结果以其自身receipt为准。
