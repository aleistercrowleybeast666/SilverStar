# ESKF20 / Invariant EKF 最小接口计划

状态：**设计，不注册组件、不生成固件、不提供可选空实现**。先完成 KF6/ESKF15
的时序、恢复和资源闭环；本计划不改变现有滤波器、SF6 或 Pure INS。

## ESKF20 的先决决定

目前没有确认额外五个误差状态的物理定义，因此不能先创建名为 `eskf20` 的实现。
现有 ESKF15 的误差维数与 nominal 四元数元素数应分别计算；不能用四元数第四个
元素或重复状态凑维数。先完成状态账本，再按实际误差自由度命名模型。

每个候选状态必须填写：物理量、单位、参考系、nominal 表示、误差自由度、连续/
离散动力学、驱动噪声、初始化与先验、量测敏感度、注入/reset Jacobian、交叉
协方差、缺测与恢复规则。可观测性必须针对实际传感器、运动和缺测条件验证，
不能因添加量测项就宣称可观测。

以下是需求调查项，不是选定的五状态组合：

| 调查项 | 需要确认的输入/条件 | 尚待回答 |
| --- | --- | --- |
| 气压偏置或环境项 | 原始气压/温度、有效独立高度参考及时间身份 | 能否与竖直位置/加速度偏置区分，是否更适合作为标定参数 |
| GNSS 天线杆臂误差 | 实测安装几何、角运动、可信 GNSS/IMU 时间 | 哪些方向能由所执行运动约束，是否有必要在线估计 |
| 传感器时间偏差/漂移 | 原始 sample/receive/PPS 等时间证据和时钟模型 | 能否与传输延迟、运动误差区分；是否先做离线标定 |
| 磁场/磁偏置或比例误差 | 原始磁量测、已知标定/安装旋转、磁参考及扰动证据 | 使用航向还是三轴模型，哪些状态具有独立观测约束 |

没有状态账本和可观测性结论前，额外五状态保持 **UNRESOLVED**，不填默认值。

## 这里 IEKF 的含义

这里讨论的是基于李群的 **Invariant Extended Kalman Filter（InEKF）**，不是
iterated EKF。先确定群结构、左/右不变误差、参考系、回缩/误差注入、偏置与杆臂
的处理，以及 P 所处的切空间。仅替换 ESKF15 的状态容器不能算完成 InEKF。
两模型对照必须转换到共同误差坐标后再比较 P，保留相同输入和外部准入条件。

## 可以复用与必须扩展的接口

现有 `Interfaces/Inc/system_navigation_backend.h` 已采用静态链接的选定 backend，
公开 `Initialize`、`Predict`、`SnapshotGet`、`Reset` 和 `BodyInputFill`，不暴露
estimator 私有类型。这一所有权/生命周期形态可以保留，不增加运行时回调注册表。

| 可复用 | 扩展前必须明确 |
| --- | --- |
| 原始/校准后 IMU、GNSS、baro 输入及 source/epoch/calibration 身份 | 新量测自己的有效性、时间、标定和物理来源合同 |
| 静态 backend 绑定、任务/ISR 所有权、结果枚举和失败后 READY 失效 | 模型特有初始化、失锁、局部模型失效与恢复状态机 |
| 有界时序队列和独立输出时间证据 | 新模型是否支持各时序策略，primary/output 的 state/P 各处于什么时刻 |
| 声明式参数、source graph、生成文件边界、后台 GUI 任务 | 独立 component/version、nominal/error 维数、状态标签和必要传感器能力 |

不要扩大所有算法的公共快照来容纳一个未定义模型。未来完整协方差通过独立的、
限长复制接口表达：调用者提供缓冲区/容量，返回实际模型、误差维数、元素数、
epoch 与 P 时间；容量不足或身份不匹配要返回明确 Result，不能部分发布。
ESKF20 若最终确为二十维误差，其完整 P 为 400 项；现有 ESKF15 的 225 项布局、
15 维注入/reset 和日志记录都不能直接改名复用。

## 最小可验证实施顺序

1. 完成状态账本和模型/传感器需求；未决时停留在本设计。
2. 建立独立双精度离线参考与有限差分/Jacobian、坐标变换和不变性测试。
3. 与 ESKF15 在相同输入、噪声与外部准入条件下对照，公开失败场景。
4. 才实现固定内存 C backend 与独立模型日志/精确 decoder/FLP 适配；保留旧日志。
5. 完成 Host 数学/故障回归、真实 analyzer、ARM 链接、资源与栈检查后再开放选项。

未来实验代码应与 builtin 可生成组件分离；不能以空返回、未更新的 state/P 或
无条件成功占位。硬件精度、MCU 时延、MSP/ISR 栈及飞行适用性另行验证。
