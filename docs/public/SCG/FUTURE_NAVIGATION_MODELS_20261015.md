# ESKF 扩展、磁力计与 InEKF 后续规划

状态：规划，不新增可选算法，不修改现有 ESKF15/SF6/INS 状态维数。本轮实现范围仍是明确的融合时序和 ESKF15 重捕获；下列模型需要独立的数据与数学合同。

## 先确定扩展状态，再命名 ESKF20

“20”目前没有经过确认的状态定义。不能为了达到维数加入五个任意状态，也不能把四元数的 nominal 元素数与三维姿态误差混算。下一阶段先列需求、每个候选状态的物理含义/单位/参考系/驱动噪声/可观测条件，再确认误差维数和名称。

每个扩展必须给出连续与离散模型、注入/重置 Jacobian、完整交叉协方差、初始化、缺测和重捕获规则，并说明哪些真实输入使它可观测。缺乏证据的量保持配置或标定参数，不默认在线估计。没有这一份状态表前不创建 `eskf20` 插件、日志尺寸或 UI 入口。

## 磁力计先完成数据与标定链

1. 选定实际传感器及安装方式后，定义原始三轴数据、单位、轴向、source/sequence、sample/receive 时间、饱和与自检状态；保留原始字节。驱动属于可信 owning plugin，decoder 只描述数据。
2. 标定记录明确硬铁/软铁参数、安装旋转、有效范围、版本和来源。不能把未标定测量当作地理航向，也不能用离线默认值补成飞行记录。
3. 单独选择航向量测或三轴磁场量测模型，明确地磁参考来源、参考系、异常检测、扰动/饱和时的普通拒绝路径和重新准入。是否在线估计磁场或偏置属于上一节的状态设计决定。
4. 先用固定输入和扰动注入验证模型、Jacobian、NIS 与完整 P，再验证板级时钟、安装、环境干扰和标定有效性。恢复定位或读取磁力计不自动赋予 READY。

## InEKF 作为独立模型验证

这里的 InEKF 指 invariant EKF，先明确群结构、左/右不变误差、坐标系、回缩映射/误差注入和协方差所处切空间。原论文的稳定性结果针对满足其条件的系统，不能直接推广为本飞控任意带偏置、杆臂、延迟和恢复策略的保证。[Barrau 与 Bonnabel，2015 版本](https://arxiv.org/abs/1410.1465v4)

偏置与机体系向量如何嵌入群结构应独立推导；后续文献专门讨论这一问题，因此不把给 ESKF15 换一个状态容器当作完成 InEKF。[The Geometry of Navigation Problems](https://arxiv.org/abs/2201.04426v4)

实施顺序为：双精度离线参考 → Jacobian/不变性与有限差分检查 → 同输入、同噪声、同外部准入的 ESKF15 对照 → 固定内存 C 实现 → 真实 analyzer/ARM 编译及完整资源报告。两种滤波器的误差协方差定义可能不同，需先转换到共同误差坐标再比较，不能只比较矩阵元素或只展示有利轨迹。

Ross Hartley 的公开 InEKF 可用作研究参考，其仓库许可证为 BSD 3-Clause；本轮没有导入该实现或增加依赖。未来若复用源码，先固定提交、保留许可证与出处，并审查它与本项目静态内存、回调、栈和目标工具链规则的差异。[项目说明](https://github.com/RossHartley/invariant-ekf)、[许可证](https://github.com/RossHartley/invariant-ekf/blob/master/LICENSE)

## 共同完成条件

新组件具有独立 ID/版本和误差状态标签，配置、生成代码、日志、精确 `.ssdecoder`、FLP Recorded Configuration/What-if 使用同一合同。旧日志和工程不被重解释。比较覆盖正常运动、静止、长短 GNSS 失锁、外部错误、磁扰、时间反序和资源耗尽；失败与未证明项完整保留。Host 数值一致性、ARM 链接和剩余 RAM 都不代表板上精度、WCET、栈安全或飞行资格。
