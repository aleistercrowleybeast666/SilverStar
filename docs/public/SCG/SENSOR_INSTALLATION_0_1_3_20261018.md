# 传感器安装配置：0.1.3 第一批设计

本批实现 SCG 中每个 IMU/GNSS 的数值 XYZ 配置、项目保存/重开、生成配置和诊断；不实现新的导航补偿。入口为 **Flight Devices → 固定原点及机体 X/Y 基准 / 各实例安装 XYZ（m）**。原点说明与各数值按 Enter 提交；勾选“已测量 / CAD 录入”才记录显示值。未勾选是未知，显式录入 `(0,0,0)` 才是原点位置。界面显示六位小数，编辑一个轴保留其他轴导入的原精度；配置工程输入范围为每轴 ±1,000,000 m，拒绝布尔、字符串、非有限数、缺轴和额外轴。

## 原点、坐标与兼容边界

原点是用户在结构图/CAD 中指定的固定机体结构参考点，独立于主 IMU、GNSS 选择、标定和导航 ENU 原点。沿用已有右手机体系，+Z 指向头部；不另造“X 向右/Y 向上”等未经定义的方向。用户在原点说明中识别原点及 +X/+Y 物理结构基准。输入为该原点至 IMU 测量点或 GNSS 天线参考点的机体系坐标，单位 m。切换主 IMU、接口或语言不移动原点、不重算坐标；安装朝向仍由已有独立配置维护。用户修改原点说明不会自动换算旧坐标，重新定义基准必须自行复核全部测量值。

旧格式 14–19 不增加原点、不把缺失坐标当零，也不根据静态标定、主 IMU 或旧杆臂猜测安装点。显式启用安装配置后保存为格式 20，旧版读取器应拒绝该格式，不丢弃新数据。实例 ID 绑定位置；删除中间实例不重编号，新增实例没有位置。实例 ID 是项目配置身份，不等价于已识别的硬件唯一标识，未来 TF 不能仅凭型号绑定。按同一实例选择另一传感器型号保留该位置，实际更换测量点后须重新测量。生成快照的新契约见 [sensor_installation_v1.schema.json](../../../contracts/sensor_installation_v1.schema.json)，完整项目 Schema 为 `apps/SCG/schemas/project.schema.json`。

本批开始时，严格 Python 解析器支持格式 14–19，默认基础格式仍为 14；完整 JSON Schema 却只列 14/15，且既有测试也固定该枚举，遗漏了后续扩展。生产打开链路 `FccgService.Project_Open → ProjectModel_Load → ProjectModel_Parse` 与生成验证 `Project_Validate → ProjectModel_Parse` 直接使用 Python 解析器，未加载此 JSON Schema；项目保存序列化 `Dictionary_Get()`，不会用旧 Schema 判断格式。源码包导出 `SourcePackage_Export` 复制文件字节，把 `schemas/` 作为随包数据，不执行 Schema 验证；本批用仅含 Schema 和示例项目的两文件导出验证了携带的契约可接受格式 20，未复制或导出整个仓库。因此先前不是生产导入器拒绝 16–19，而是已发布的机器契约与实现不一致。本批已补齐完整 Schema 至 14–20，并以真实 JSON Schema 验证器检查序列化、保存重开和拒绝用例；验证器只加入开发依赖，生产解析器继续负责插件、资源、几何和运行时能力等语义检查。

| 格式 | 保存时的扩展边界 |
|---|---|
| 14 | 基础工程，未启用新扩展时继续使用 |
| 15 | 地面多无线电实例 |
| 16 | 逐实例无线电模块/功率 |
| 17 | 功能档与非递归档位预设 |
| 18 | 显式 NIS 概率输入 |
| 19 | 原生 USB 参考及证据引用，引用本身不授予准入 |
| 20 | 显式固定结构原点与逐实例安装位置，可与上述扩展共存 |

格式 20 是新增数据与未知/已测量语义的可识别版本边界，不是产品版本整体升级。旧项目不自动升至 20；只在用户启用安装配置后写入 20。旧扩展与嵌套预设完整保留，禁止把新坐标塞进格式 14–19，也不自动降级、迁移杆臂或推导原点。空原点说明允许保存为草稿，但生成验证仍拒绝；JSON Schema 结构校验通过不表示安装测量或补偿已验收。

ESKF15 的旧 `lever_arm_body_x/y/z_m` 继续是它原有导航参考点至 GNSS 的全局机体系杆臂，进入原有位置/速度观测路径；历史项目的物理参考点不能仅凭字段恢复。本批不把旧字段迁入某个实例，不把新的结构原点冒充旧导航参考点，也不改旧生成常量。多个 GNSS 的已有路径仍共用这个全局值，含故障切换路径，诊断要求复核。即便新安装 XYZ 与旧值不同，也保持两者独立并明确告知，不能视为已完成杆臂迁移。

## 配置流与实际能力

项目 `sensor_installation` 保存固定结构参考说明、body/m、测量/CAD 来源；每个设备可选 `position_body_m:{x,y,z}`。新扩展通过严格解析与编辑/生成验证。空原点说明可以作为编辑草稿保存，生成时以 `INSTALLATION_ORIGIN_UNDEFINED` 拒绝；IMU/GNSS 以外的实例位置报错。完整原点说明仍需人工确认物理含义，文本存在不构成几何验证。

生成器在自身拥有的 `Generated/` 下输出 `project_sensor_installation.json` 及 `Inc/project_sensor_installation.h`。JSON 保存实例 ID、未知/null 与实测坐标、轴向约定、旧 ESKF15 输入及生效全局值；头文件提供独立数据宏并固定 `PROJECT_SENSOR_INSTALLATION_RUNTIME_APPLIED=0`。这些配置没有被运行时使用，不新增源图节点、滤波器状态或驱动 ABI。普通再生成只更新受管输出，继续保留项目拥有的组件源码。项目指纹覆盖安装配置，改动后旧生成身份失效。

| 路径 | 本批能力与限制 |
|---|---|
| 所有 IMU/GNSS 实例 | XYZ 可输入、保存、重开、生成；未消费于运行时补偿 |
| ESKF15 | 仅原有独立全局 GNSS 杆臂有效；不支持新坐标派生或按实例切换杆臂 |
| KF6 / SF6 / Pure INS | 未实现安装位置/杆臂补偿 |
| 多 IMU | 无动态加速度测量点换算，不因切换主 IMU 改结构原点 |
| 日志与 TF | 本批不扩展现有 decoder/记录格式，不把生成配置当作录制过的 TF |

界面常驻说明及编辑/生成诊断 `INSTALLATION_CONFIGURATION_ONLY` 覆盖所有路径；非零坐标另报 `INSTALLATION_NONZERO_UNCOMPENSATED`，逐项列出未补偿实例，并明确“配置验证/生成成功不证明补偿生效”；ESKF15 另给出 `INSTALLATION_LEGACY_GLOBAL_ARM`。警告允许生成配置以独立验收，不表示可以依赖这些坐标飞行。后续启用补偿前，必须明确导航状态参考点、GNSS 天线参考点、不同 IMU 的参考与切换语义，完成数学和运行时故障路径审查及专项测试。

## 上电校准、安装标定与未来向导

目标上电流程只读取已提交安装参数，执行健康检查，并仅在满足静止条件时估计陀螺零偏。它不求解安装 XYZ，也不运行安装标定向导。本批没有改现有启动状态机；该目标流程仍待后续实现和验收，失败不得留下虚假的 READY。

安装标定仅允许维护串口显式触发；不得由普通上电、AIR 指令或主传感器切换隐式触发。未来向导分开维护：

- IMU 等传感器的内参（偏置、比例和轴间误差等）不需要其在板上的 XYZ；安装 XYZ 属于不同测量点的动态杆臂模型输入，两者不能混为一谈。
- 组内/组间外参为按传感器标识关联的 TF。机体平移、朝向、传感器内参及其校准质量/有效性分别表达，不能用一个成功标志代替全部能力。
- 磁软铁/硬铁内参可以独立拟合。后续可研究用多个静止姿态联合估计校正后磁坐标到 IMU 的有效旋转与未知磁倾角，但必须审查姿态激励、可观性和歧义；本批不实现求解，也不宣称磁航向已经可用。

向导候选结果先验证后提交，失败保留旧结果及其身份；不得用失败或不完整候选覆盖已有效结果。TF 存储实现由另一任务负责，本批未编辑存储代码、不做 SPI Flash。维护触发、内参/外参求解、按标识存取 TF、原子提交和失败保留旧结果的运行时实现均不属于本批已完成项。

专项入口为 `apps/SCG/tests/test_sensor_installation.py`，覆盖未知/零、格式与单位拒绝、非有限值、固定原点、多实例与主 IMU 切换、输入精度、双语 UI、文件往返、旧杆臂隔离、源图不变以及保留用户源码的再生成。小规模命令、结果、环境、源码哈希和 GUI 截图路径记录于本次版本化任务证据目录 `.work/sensor-installation-0.1.3-20261018`；测试生成物位于 `apps/SCG/.work/sensor-installation-0.1.3-20261018`。没有硬件或飞行证据；配置头编译不代表整固件编译/链接、运行时补偿或 Power of Ten 合规。
