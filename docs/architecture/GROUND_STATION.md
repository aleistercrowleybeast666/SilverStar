# Ground Station firmware boundary

    Flight Controller ── AIR packet ── Ground Station MCU ── GSP byte stream ── GSHC

Ground Station MCU is firmware generated by FCCG; GSHC is the separate PC application. Ground forwards an AIR frame opaquely. It does not decode Flight commands, change payloads, own LOCK/START semantics, or change AIR M0. Ground C contains a bounded radio TX queue, a bounded PC output queue, ACK/GS_STATUS, radio statistics, RSSI/SNR forwarding, and parser CRC accounting. It reuses the SX1281 chip driver with a Ground radio adapter; the Flight telemetry adapter is excluded from Ground generation.

The behavior reference is [GS_SS1](https://github.com/aleistercrowleybeast666/GS_SS1), commit 7fe0f61142c7360f7dbae0ac0000036315631320. This is a reference implementation, not a runtime dependency. Ground Core and its application entry are SilverStar code; the legacy application `main.c`, Makefile and build outputs are excluded. The F1 family plugin imports the reference's ST vendor HAL/CMSIS source, and the board plugin preserves only its IOC and CubeMX hardware source snapshot. [GSP contract](../../contracts/gsp/README.md) and shared golden vectors bind the C implementation to GSHC's Python implementation. The formal bridge emits only binary GSP; the reference's ASCII diagnosis is outside that mode.

The Ground PC Interface is UART 8N1 with the configured CubeMX baudrate, or USB Device CDC Virtual COM. Both use PcByteStream_Read/Write and the same GSP frames. GSHC uses its existing pyserial COM backend for either physical UART adapter or USB CDC. Ground's USB CDC selection requires an imported CubeMX project with USB Device CDC capability, callback, descriptors, and complete middleware sources; a standalone .ioc cannot supply those files. The RX ring drops excess bytes and counts overflow. `PcByteStream_Write` returns explicit `OK`, `BUSY`, or `ERROR`: BUSY retains the bounded queued frame for retry; ERROR increments a fault counter available through `GroundBridge_DiagnosticsGet` and returns a bridge error.

GS_SS1's `Ground_Station0.5.ioc` targets STM32F103C8T6, 72 MHz HCLK, SPI1 9 Mbit/s and USART1 230400 with DMA. The original PCB has operated on hardware, as reported by the user; the board plugin records this as a hardware-validated reference for its topology. The newly generated SilverStar Ground UART firmware builds and links for the official F103C8 limits, but has not been burned and tested on that PCB. USB CDC is likewise not validated on GS_SS1. Flight SS0.5 remains absent from the Ground production board selector.

For a family declaring the STM32 HAL Receive-to-Idle adapter and a UART resource with RX and TX DMA, Ground generation uses bounded DMA buffers for both directions. An IDLE or full receive event copies at most 128 bytes into a 512-byte single-producer/single-consumer ring. Excess bytes are dropped and counted. The half-transfer interrupt is disabled so a chunk has one owner. TX copies one bounded GSP frame before starting DMA; `HAL_BUSY` leaves the bridge's queued frame pending. The GS_SS1 IOC enables USART1 and both DMA channel IRQs. Hardware still needs a new board smoke to establish real-time behavior.

Each Ground bridge process call reads at most 64 PC bytes, handles at most four radio RX packets, and drains at most four queued PC frames per flush. Invalid radio packets consume the same four-packet budget, so sustained corrupt traffic cannot create an unbounded processing call. UART and USB CDC each read at most 512 ring bytes per call; the bridge's 64-byte request is tighter. USB receive callbacks inspect at most 512 input bytes and count all skipped bytes on overflow. Host tests exercise continuous invalid radio input and USB receive overflow/backpressure. These are work bounds, not target WCET evidence.

The generated F103 UART reference separates first-party C from CubeMX/ST vendor C. First-party sources compile with the same strict warning family as Flight and carry a generated `power10-check` target; the checker scans Ground bridge, GSP, radio, STM32F1 glue, and generated adapters without treating vendor HAL as first-party. The exact F103 linker reserves zero heap. The latest `arm-none-eabi-size` output is text 20,844, data 12, bss 14,112 bytes, within the official 64 KiB Flash and 20 KiB SRAM limits. Ground and Flight Power of Ten checks both report zero findings. These are software and static bounds; new Ground firmware hardware integration and target WCET measurement remain pending.
