## 问题与修复

用户指定的旧文件位于
`.work/dev013_reacq_integration01/offline_acceptance08/eskf_emitted10/Devices/GNSS/NEO_M9N/Adapter/Src/neo_m9n_system_adapter.c`。
函数始于第 408 行，原转换位于第 434 行。其字节与 owning plugin payload
一致，SHA-256 为
`0cd22b1274df54133e84d4c81c7b1447719efae8c13726a809160281bd5285c4`。
旧工程作为证据保留，本次没有覆盖它。

实际修复位于
`apps/SCG/plugins/builtin/silverstar_device_gnss_neo_m9n/payload/Devices/GNSS/NEO_M9N/Adapter/Src/neo_m9n_system_adapter.c`：

```c
/* before */
sample->velocity_enu_mps[2] = (float)(-data.velD) * 0.001f;
/* after */
sample->velocity_enu_mps[2] = -(float)data.velD * 0.001f;
```

`velD` 是 NAV-PVT 的有符号 32 位 mm/s 值。旧表达式先做整数取负，
`INT32_MIN` 的正值不能由该整数类型表示。新表达式先转换为 `float`，
再取负和换算单位；整个 `int32_t` 范围转换及乘法结果均为有限浮点数。
端点会发生正常的单精度舍入，不新增饱和、报错、断言或业务过滤规则。

整段转换的 E/N 轴、有效性判断、质量评估返回值、快照获取、时戳、
序号、方差及配置就绪门禁保持原语义。没有新增状态、分支、循环、
分配、接口、头文件、回调或同步操作。该变更不扩张项目安全例外。
对本次数值转换边界的专项审查成立，不据此扩展到整个文件的所有关键契约。

## 专项对照

扩展现有 `Tests/Host/test_neo_m9n_adapter.c`，使用真实校验和有效的
NAV-PVT 帧，经 UART mock、设备解析及公开 instance 接口取得 sample。
检查解析后的 `raw.velD` 未变，ENU U 有限、幅度及符号正确，E/N 与有效掩码
保持原期望。参考值使用 double 除法，容差为浮点精度范围；普通用例不能
代替这组端点检查。

9 个输入：`INT32_MIN`、`INT32_MIN+1`、`-400`、`-1`、`0`、`1`、`400`、
`INT32_MAX-1`、`INT32_MAX`。在 `-O0`、`-O2` 下分别执行普通编译和
`-fsanitize=signed-integer-overflow -fsanitize-undefined-trap-on-error` 编译。
这是 Host 溢出检测；陷阱不是 MCU 恢复试验。

| 对象及配置 | 结果 |
|---|---|
| 修复前原始 adapter，普通 `-O0` / `-O2` | 各 exit 1；8340 checks、3 failures，全部针对 `INT32_MIN` 的值及符号 |
| 修复前原始 adapter，溢出检测 `-O0` / `-O2` | 各 exit 3221225501，即 `0xC000001D`；输出 `checking velD=-2147483648` 后触发陷阱 |
| 修复后 owning adapter，普通及溢出检测，两种优化 | 每次 8340 checks、0 failures |
| 新生成 adapter，溢出检测，两种优化 | 每次 8340 checks、0 failures |
| M9N 协议与启动回归 | 25600 checks、0 failures |
| M9N 多实例回归 | 42 checks、0 failures |
| 最终 pytest / Ruff | 3 passed / passed |

修复前普通编译的 `INT32_MIN` 输出为 **`-2147483.75 m/s`**；修复后为
**`+2147483.75 m/s`**。数学换算值为 `+2147483.648 m/s`，差异属于
float 舍入。这里证明的是整数全域的转换安全，不是该极端速度的物理可信性。

生成输出逐字节核对 owning adapter 和 Host C fixture。生成输出的专项 Host
运行显式复用既有 MultiInstance 资源 fixture；这不是真实硬件或生成 UART
资源初始化的证明。协议和多实例回归的 fixture 范围也保留在实际命令中。

ARM 使用同一新工程的完整实际编译参数重新编译修复前 adapter 作对照。
修复前反汇编存在 `negs r3, r3`，修复后路径直接做有符号整数到浮点转换，
不再对原始 `velD` 整数取负。内联后的
`NeoM9nGnssInstance_LatestSampleGet` 两者 `.su` 均为 120 字节静态帧。
这只是该函数的编译器栈帧结果，不是任务或 MSP/ISR 的栈证明。
