## 已核实的问题

- 真实 MAG 控制单元的负例中，采集资源 `owner=1` 时，
  `SystemMagCalibration_PacketApply` 仍返回 Ok，而期望 Busy。
  实际 C 入口尚未取得安装模块的 lease，不能用 PC/mock 互斥代替生产入口覆盖。
- CAL 的 Start/Face/Stop/Reset 和 ALIGN Start/Stop/Reset 的现有 action/lifecycle
  保留以调用结束为边界；采集继续运行时这些 action 已结束。新增 lease 必须覆盖异步采集
  和清理全生命周期。CAL→ALIGN 安全失效是内部调用，不能直接嵌套两个排他的顶层 claim。
- START 同时存在排队入口 `SubmitStart` 和直接入口 `StartTransaction`，以及 FlightTask
  消费请求的 `Process`。只在 AIR/串口 dispatcher 加检查不足以关闭内部入口。
- TF 维持 Logger/介质所有者，当前 512 字节原子对象及其双槽仍需保留；不能扩大为16 KiB
  整包或覆盖 MAG 槽。新候选必须先独立 staging、分块校验，最后才发布完整代次引用。

## 预算与两个实现方案

当前完整 ELF 主 SRAM 102292/102400，余108；CCM 64896/65536，余640。
既有安装采集门槛还要求 `cap_ccm_bytes=2048`、新增主 SRAM 为0，不只检查芯片总容量。

| 方案 | 新状态布局 | 成本与限制 |
|---|---|---|
| 独立分配 | 上下文60 B＋维护块64 B＋6个token共24 B | ARM sizeof为148 B；放主 SRAM 超40 B，且不满足新增主 SRAM 为0。不能直接采用。 |
| 使用安装模块未使用的预留区 | Control 预留80 B→6 token 24 B＋去掉重复token的上下文56 B；Frozen 尾部预留80 B→块64 B＋store token4 B | 布局草案为80 B和68 B；预期保持已分配状态1960 B、wire 28 B。必须经明确的类型、边界和所有权改造及实编验证，不能仅靠 sizeof 宣称安全。 |

第二种方案不借用活跃样本槽、既有日志邮箱或 DMA 缓冲；会把安装模块中的未使用预留字节
改成持久化协调状态，因此需要确认这项所有权取舍。实现不得暴露可变裸指针给其他任务：
Serial/控制入口只提交有界拷贝，Logger 获取独占工作请求并处理，完成后才发布结果。

磁力计、CAL、ALIGN、START、配置和 TF 顶层入口分别取得/延续/释放自己的代次token；
迟到完成先核对原有 request/generation，再能释放。内部安全失效保留安全语义，不能被
另一个顶层 lease 阻断或通过“同owner自动重入”绕过。取消/失败仍需等待真实消费/I/O结束，
没有确认关闭不能发布可复用状态。默认OFF，真实 BEGIN/APPLY/SAVE 继续关闭。

采用预留区方案后，仍须实现并实测：合法和冲突入口、CAL→ALIGN调用链、排队/直接START、
TF块重试/断线/取消、旧代保留、提交ACK不确定结果、父代失效及完整快照；运行最终源码的
适用完整回归、原始生成门禁、真实分析器、完整 ARM 链接与资源/栈报告。
