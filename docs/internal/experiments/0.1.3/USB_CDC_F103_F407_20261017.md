## 后续默认方向与重新启用

后续USB连接的默认评估方向为 **USB–UART/串口桥接，复用既有UART/AIR链路及其READY/超时/背压语义**。这是一项后续路线优先级，不是已经实现的桥接功能。本文不确认具体桥接芯片、板卡、电气接线、驱动或性能；它们仍需选型和验证。ACK不能替代AIR M0/控制器READY，也不能因PC端出现串口就宣布整链可用。

原生CDC候选保持封存。只有用户重新决定使用时，才按以下顺序启动验收：

1. 明确所选实际芯片、板卡、Cube/HAL版本、CDC ABI、控制器、时钟、非DMA/单缓冲条件及桥接/原生路线；不自动扩展其他STM32。
2. 核验下列证据及manifest哈希、输入完整性和新基线前像；证据缺失即标为缺失，不能悄悄替换旧结果。先在隔离工作区按顺序合成58路径产品快照。
3. 对同一最终快照做补丁整链检查及相关SCG/USB回归、错误/生命周期回归、真实分析编译、ARM链接、source graph/向量/库/栈报告；明确复用和重编范围，不拼接旧通过。
4. 保留原始gate。若要求其退出0，只在冻结的两份LL、既有owner和必要测试内处理已列结构项；main与故障入口分别审查，不扩大allowlist、不机械改写循环、不开始全HAL无限重构。
5. 对关键契约和故障入口记录明确结论；未证明项保持NOT_PROVEN。桥接方案亦需验证实际驱动、串口断连、丢包、背压与会话/READY，不因复用UART而跳过验收。
6. 取得明确硬件授权后，才在匹配板卡验证枚举、收发内容/长度、持续负载、断连/重连、暂停/恢复、错误路径、时钟和IRQ/栈/时序等；这一步目前未执行。
7. 完成最终同快照集成验收后，再由主工作区唯一写者决定集成；发布/推送另需授权。此前继续标记有限实验候选，不进入正式用户支持矩阵。
