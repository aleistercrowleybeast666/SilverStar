# 二维水平轨迹

GSHC 在现有三个顶层页之后追加“水平轨迹”页，保持飞行页六曲线和 3D
布局。六曲线保持既有十秒缓冲，二维图使用独立的当前任务历史及开伞时刻，轨迹采用东 E / 北 N
等米距轴，相对高度 U 着色。数据后处理的图表导出每页追加一张
`Trajectory2D` PNG，沿用既有时间范围、分页、语言和主题配置。

两端绘图、数据缺口、起止点及事件语义见
[FLP/GSHC 共同轨迹约定](../FLP/Horizontal_Trajectory.md)。共同实现以同字节
独立模块保留在两端安装包，FLP 回归校验其一致性，不引入跨应用运行时依赖。

二维图默认展示当前任务全部可用样本。历史最多保留 18,000 个原始样本
（正常 5 Hz 下约一小时），满容量后裁剪最早样本，不降采样、不插值。
图标题明确给出省略样本数，起点改标“范围起点”；已裁掉的开伞位置不补造。
开伞时刻独立保存在该任务历史中，不随 200 项普通事件列表淘汰。
同时间、NaN 位置、长时间缺口由共同几何服务断线；逆序/非法时刻被拒绝并
计数，下一有效位置前强制断线。模型保留原始 FLIGHT_STATE 时刻，迟到的
START 不重写已经保存的样本时刻。LANDING 后历史冻结，并按记录的落地时刻
限制可见范围。图的终点只有落地后标为“终点”，运行中仍为“范围终点”。

串口/协议线程不访问该历史；Controller 在既有 GUI 邮箱消费路径 O(1) 追加。
满任务图绘制合并为最多每 500 ms 一次流式更新，隐藏页不绘制，六曲线刷新
周期保持不变。语言、主题及首次显示立即刷新。
断开重连及飞控会话替换创建新状态，清空任务位置、裁剪计数和开伞时刻。
落地后的显式 MISSION_START 清空旧任务历史；活动任务中的重复或迟到 START
保留已有历史。重新绑定相同模型不清空任务，绑定新模型立即替换显示。

`test_mission_trajectory.py` 包含 350 秒/5 Hz 与早期开伞事件淘汰、真实容量边界、
断线、新任务和重连回归。`tests/validation/mission_trajectory_probe.py` 是仅使用
合成输入的原生 Qt 窗口检查，保存中英 1280x720/900 全程图、容量标识及
原六曲线截图，同时执行提交 553ad43 的旧 GUI 代码记录十秒窗口的修前失败。
